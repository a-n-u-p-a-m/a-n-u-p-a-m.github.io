01The premise, and why it is unusual

Mechanistic interpretability has a canon, and that canon is almost entirely about transformers on text. This project asks what happens when you point the same toolkit at a different architecture on a different data type: a Temporal Graph Network processing a stream of timestamped events.

A Temporal Graph Network (TGN) is the dominant architecture for learning on continuous-time dynamic graphs — graphs where edges arrive as a timestamped stream rather than sitting in a fixed adjacency matrix. Fraud rings forming in a payments network, accounts coordinating on a social platform, packets traversing a compromised subnet, a cascade of trades across venues: these are all event streams, and TGNs are what people deploy on them. They also happen to be architectures nobody has opened up.

That gap is the project's entire reason for existing. The claim in the title — "first systematic interpretability study of a Temporal Graph Network" — is a claim about an empty space in the literature, not about inventing a new method. The methods are borrowed from transformer interpretability (activation patching, ablation, causal mediation). The contribution is porting them to a recurrent, per-node-memory architecture, discovering that the port is harder than it looks, and reporting what breaks.

The question behind the question

Every interpretability result has the form "intervening here changes the output by this much." That sentence is only meaningful if two things are true:

  1. The intervention actually did what you think it did (it reached the computation you aimed at).
  2. The effect size is measured against a control that isolates the specific thing you care about, not just "something was perturbed."

Both assumptions fail silently and routinely. A large chunk of this project is machinery built to catch those failures — and the most interesting results are the ones where the machinery caught the author's own earlier conclusions being wrong. That stance, treating instrument validity as a result rather than a footnote, is discussed in §9, and is arguably the real deliverable.

02What a Temporal Graph Network actually is

Before anything can be reverse-engineered, it helps to be precise about what is being reverse-engineered. This section builds the architecture from first principles, and names the alternatives that were not chosen.

Two kinds of dynamic graph

The literature splits graphs that change over time into two families, and the split determines which architectures are even applicable:

FamilyRepresentationTypical approachWhat it loses
DTDG
discrete-time dynamic graph		a sequence of static snapshots \(G_1, G_2, \ldots, G_T\), each a full adjacency matrixrun a static GNN per snapshot, then an RNN over the snapshot embeddingseverything inside a snapshot interval — ordering, and the exact gaps between events
CTDG
continuous-time dynamic graph		a stream of timestamped events \((u, v, t, \mathbf{e})\)maintain per-node state, updated as each event arrivesnothing by construction; the cost is that you cannot batch over time

This task is CTDG by necessity. The label depends on whether \(t_2 - t_1 < \Delta\) where \(\Delta = 5.0\) on a timeline of length 100 — a distinction a snapshot model would quantise away unless its snapshot interval were finer than \(\Delta\), at which point it is a CTDG model with extra steps.

The four modules

Rossi et al. (2020) factored the CTDG problem into modules that most subsequent work has kept. In the order an event flows through them:

  1. Memory. Every node \(v\) carries a state vector \(s_v \in \mathbb{R}^{d}\), initialised to zero and updated whenever an event touches \(v\). This is the node's compressed history. It is not a learned embedding in the nn.Embedding sense — there is no parameter per node; the parameters are in the update function, and the state itself is activation, not weight. That distinction is what makes per-node memory interpretable at all: you can ask what a particular sample's node-\(B\) memory contains, which is meaningless for a static embedding table.
  2. Message function. When event \((u, v, t, \mathbf{e})\) arrives, compute a message for each endpoint from both endpoints' current memories, the elapsed time, and the edge features.
  3. Message aggregator. If a node is touched several times in one batch, combine the messages (mean, or keep the last).
  4. Embedding. Produce the final node representation used downstream, typically by graph attention over temporal neighbours.

The architectures that were not used, and why

The selection logic is worth stating plainly, because it generalises: when the goal is to understand a mechanism, pick the architecture where the mechanism is a first-class object. TGAT would likely score similarly on this task, and would have been easier to train. It was the wrong choice because a study of memory circuits needs a memory.

One deliberate simplification

The embedding module — module 4 above, normally a temporal graph-attention layer — is replaced with the identity function. The source states the reason directly:

class GraphEmbedding(nn.Module):
    """For the motif completion task, we use the MEMORY STATES directly
    (identity embedding) since the task tests memory-based temporal reasoning.
    Adding a graph attention layer here would complicate MI analysis
    without improving task performance."""

This is a real trade-off and should be read as one. An attention layer would add a second place where composition could occur — a node could aggregate its neighbours' memories at readout time, independently of what its own memory accumulated. Removing it means the study's central finding (§7) is a statement about memory composition specifically, not about every route by which information could combine in a full TGN. The cost of including it would have been an extra, confounded pathway in every patching result. The honest framing: this is the simplest architecture that still exhibits the phenomenon of interest, and the finding should be re-tested with attention enabled before being generalised.

03The task: temporal motif completion

You cannot reverse-engineer an algorithm unless you know what algorithm would be correct. So the first design decision was to build a synthetic task with a known ground-truth rule, rather than take a real dataset where the right answer is unknown.

The rule

Each sample is a stream of timestamped directed edges over 50 nodes. Three nodes are designated as candidates: \(A\), \(B\), \(C\). The label is:

\[ y = 1 \iff \exists\, t_1, t_2 \;:\; (A \to B \text{ at } t_1) \;\wedge\; (B \to C \text{ at } t_2) \;\wedge\; 0 < t_2 - t_1 < \Delta \]

with \(\Delta = 5.0\) on a timeline running from 0 to 100. In words: did influence flow from A to C, through B, fast enough to count?

This is the smallest non-trivial temporal reasoning task. To answer it, the model must simultaneously track three things that a static graph model cannot: who (node identity must match — the \(B\) in \(A\to B\) is the same \(B\) in \(B \to C\)), when (ordering: \(t_2\) after \(t_1\)), and how long (the gap is under \(\Delta\)). Break any one of the three and the label flips.

Why synthetic, and what it costs

The alternative was a real CTDG benchmark — Wikipedia edit streams, Reddit interactions, the Elliptic bitcoin graph. Each has the fatal property that nobody knows the correct algorithm, so "the model computes X" cannot be checked against "the model should compute X."

Synthetic data buys three things that make causal claims possible: a ground-truth rule; minimal-pair counterfactuals (a negative is a positive with exactly one edge changed, so the positive/negative contrast isolates one variable); and full control over confounds. It costs external validity — see §12 — and it transfers the entire burden of rigour onto the generator, which is why the next subsection is as long as it is.

Five ways to be wrong

Negative samples are not drawn independently. Each one is a positive sample with exactly one minimal corruption applied, which makes the positive/negative contrast a clean counterfactual rather than a comparison of two unrelated graphs. The generator implements five strategies:

The anti-shortcut arms race

A synthetic task is only as good as its defences against being solved the lazy way. Each sample is wrapped in noise edges, distractors and partial motifs — but the genuinely instructive part is what the author found after those defences were in place.

The leak that six audits missed

Three of the five corruptions (topology_break, source_shuffle, edge_deletion) replace an edge inside the candidate triple with one pointing outside it. An earlier degree-parity safeguard restored each candidate node's total degree by adding an edge to a non-candidate neighbour — so total degree was preserved exactly, and a degree-based audit saw nothing.

But the count of edges among \(\{A,B,C\}\) was now systematically one lower in those negatives. The single rule internal_count >= 4 → positive reached 78.2% balanced accuracy on the real generator. A model scoring 85% could have been doing almost nothing else.

The fix, _enforce_structural_parity(), pads every sample — positive or negative — up to a fixed canonical profile (internal_edges=4, deg_A=3, deg_B=4, deg_C=3) using only the four candidate-internal edge orientations that cannot participate in an \(A\to B\to C\) chain: \(A\!\to\!C\), \(C\!\to\!A\), \(B\!\to\!A\), \(C\!\to\!B\). Those are inert ballast regardless of their timestamps. tests/test_generator_parity.py now asserts that neither statistic carries label information.

The padding routine is a small constraint-satisfaction problem, and reading it shows why the four safe orientations matter. The deficit in internal edge count must be closed without overshooting any single candidate's degree, so the code searches over how many of each safe orientation to add:

for n_ac in range(need_int + 1):
    for n_ba in range(need_int + 1 - n_ac):
        n_cb = need_int - n_ac - n_ba
        if (dA + n_ac + n_ba <= t_A and dB + n_ba + n_cb <= t_B
                and dC + n_ac + n_cb <= t_C):
            chosen = (n_ac, n_ba, n_cb)

Each orientation contributes degree to a different pair — \((A,C)\) and \((C,A)\) to \(A\) and \(C\), \((B,A)\) to \(A\) and \(B\), \((C,B)\) to \(B\) and \(C\) — so the three counts are exactly the degrees of freedom needed to hit a three-way degree target. Remaining degree shortfalls are topped up with edges to non-candidate nodes, which add degree without touching the internal count. A final assertion verifies the profile was reached, and the function raises rather than silently producing an off-profile sample.

The lesson generalises past this codebase. The project ran a six-baseline shortcut audit (scripts/audit_model.py) — feature-only, degree-only, event-count, timestamp-only, node-identity, candidate-timing — training trivial MLPs to predict the TGN's own outputs. None of the six could see this leak, because the leak lived in a statistic none of them computed. A clean audit is evidence of absence only for the shortcuts you thought to test.

Two further defences are worth naming because they are the kind of thing that silently ruins synthetic benchmarks:

  • Event-count parity. _pad_events_to_target() pads every sample to an identical global event count, so graph size carries no signal. It raises rather than truncates if a sample overshoots — a loud failure instead of a quiet bias.
  • Post-generation validation. Positives are regenerated unless exactly one \(A\to B\to C\) completion exists; negatives are regenerated from scratch (not patched) if noise accidentally completes the chain. Patching would preserve the event count but destroy the corruption's semantics.

There is also a quiet numerical guard worth noticing. Timestamps are drawn from a continuous uniform, but float collisions and max_time clipping can produce exact ties, and the model consumes events in sorted order. The generator jitters duplicates by \(10^{-5}\) without re-sorting, and the comment explains why: re-sorting the time array independently would misalign it from the already-sorted src, dst and msg arrays. An assertion then confirms uniqueness. This is a one-line bug that would have produced a subtly wrong dataset with no error message.

The GRU, from first principles

A Gated Recurrent Unit maintains a hidden state and decides, per dimension and per step, how much of it to overwrite. The motivation is the vanishing-gradient problem: in a plain RNN, \(s_t = \tanh(W[s_{t-1}, x_t])\), the gradient through \(k\) steps carries a factor \(\prod \partial s_{i}/\partial s_{i-1}\), which shrinks geometrically and destroys any long-range credit assignment. Gating fixes this by giving the state an additive path.

The four quantities, in the order the code computes them:

\[ \begin{aligned} z_t &= \sigma\!\big([\,m \,\|\, s\,]\,W_z + b_z\big) &&\textit{update gate — how much to overwrite}\\[2pt] r_t &= \sigma\!\big([\,m \,\|\, s\,]\,W_r + b_r\big) &&\textit{reset gate — how much history to forget}\\[2pt] \tilde{h} &= \tanh\!\big([\,m \,\|\, r_t \odot s\,]\,W_h + b_h\big) &&\textit{candidate state — what would be written}\\[2pt] s' &= (1 - z_t)\odot s \;+\; z_t \odot \tilde{h} &&\textit{the write} \end{aligned} \]

Reading equation (4) carefully matters for everything downstream. When \(z \to 0\), \(s' \to s\): the state passes through untouched and \(\partial s'/\partial s \to 1\), which is the additive gradient path. When \(z \to 1\), \(s' \to \tilde h\): the old state is discarded entirely. The two gates do different jobs — \(r\) controls what history enters the candidate, \(z\) controls how much of the candidate reaches the state — and conflating them is a common source of confusion. §8 turns on exactly this distinction.

Design decision: hand-rolled, not nn.GRUCell

PyTorch ships nn.GRUCell, and it is faster: a fused CUDA kernel computing all three gates in one batched matmul with no Python-level intermediates. This codebase does not use it, and that is the single most consequential engineering decision in the project.

The problem: a fused kernel is opaque. You can read its input and its output, and nothing in between. \(z_t\), \(r_t\) and \(\tilde h\) never materialise as tensors you can hook.

Alternatives considered and rejected: (i) Forward hooks on the module — these fire on the module's inputs and outputs only, so they see exactly what you could already see. (ii) Finite-difference probing — perturb the input, observe the output, infer the gates; this is indirect, noisy, and cannot write a gate value, which the causal arms require. (iii) A custom autograd Function wrapping the fused kernel — preserves speed but reintroduces the same opacity inside the kernel. (iv) Monkey-patching ATen internals — version-fragile and effectively unreadable.

The cost paid: a Python-level GRU over ~40 sequential event steps is meaningfully slower than the fused path, and the model is small enough that this is mostly kernel-launch overhead rather than arithmetic. For a 121K-parameter model on a T4, that is an acceptable trade. For a production-scale model it would not be, which is a real constraint on scaling this methodology.

An autograd detail that matters

The memory bank is written back with a clone-scatter, not an in-place indexed assignment:

idx = node_ids.unsqueeze(-1).expand(B, D).unsqueeze(1)
self.memory = self.memory.clone().scatter_(1, idx, memory_write.unsqueeze(1))

The comment in the source explains why: tensor[idx] = val silently breaks the gradient chain on CUDA for sequential read-write memory patterns in some PyTorch 2.x versions. Backpropagation-through-time across ~40 event steps would have failed quietly — the model would train, badly, and nobody would know why. Clone-scatter creates explicit autograd nodes instead.

The cost is memory: cloning a \((B, 51, 128)\) tensor at every one of ~80 memory writes per forward pass means the autograd graph holds ~80 copies. At batch 32 that is roughly 67 MB of activations for the memory bank alone — affordable here, and the reason batch_size is capped at 32 in the pipeline scripts.

Time encoding, and the theory under it

Elapsed time \(\Delta t\) is projected through learnable frequencies:

\[ \Phi(\Delta t) = \big[\cos(\omega_1 \Delta t), \ldots, \cos(\omega_8 \Delta t),\; \sin(\omega_1 \Delta t), \ldots, \sin(\omega_8 \Delta t)\big] \in \mathbb{R}^{16} \]

with \(\omega \in \mathbb{R}^{1\times 8}\) trained by gradient descent. This is a Time2Vec / TGAT-style functional encoding, and its justification is Bochner's theorem: a continuous shift-invariant kernel \(k(t_1, t_2) = \psi(t_1 - t_2)\) on \(\mathbb{R}\) is positive-definite if and only if it is the Fourier transform of a non-negative measure. Sampling frequencies from that measure gives a finite random-feature map whose inner product approximates the kernel:

\[ \psi(\Delta t) \;\approx\; \frac{1}{d}\,\Phi(\Delta t)^{\!\top}\Phi(0) \]

In plain terms: a sinusoidal basis with learned frequencies can represent any reasonable notion of "these two times are close," and gradient descent picks which notion. The alternative encodings each lose something:

EncodingProblem for this task
Raw scalar \(\Delta t\)a single unbounded feature; the downstream MLP must learn a sharp threshold at 5.0 from a linear input, which is possible but needs capacity the model would rather spend elsewhere
Fixed sinusoids (Transformer-style)frequencies are a geometric series chosen for sequence positions, not for a task with a specific physical timescale; nothing ties them to \(\Delta = 5\)
Learned bucket embeddingsdiscretises time, which is exactly what a CTDG model exists to avoid; also puts a hard boundary wherever the bucket edges fall
Learnable sinusoidsChosen. Continuous, differentiable, and the learned \(\omega\) is directly interpretable — see below.

That last property is what makes experiment T5 possible. With eight parameters, the encoder is the smallest thing in the model and the most directly inspectable: T5 reads \(\omega\) straight out of each checkpoint's state dict with no forward passes at all, and asks whether any learned frequency has implied period \(2\pi/\omega \approx 5.0\). It is the cheapest experiment in the project and potentially one of the most informative.

Two readouts, and the reason for the second

The primary classifier reads the memories of \(A\), \(B\), \(C\) after all events have been processed. This is the standard TGN design, and it has a problem that the project discovered experimentally: by the end of the sequence, later events touching \(B\) have overwritten whatever \(B\) knew at the moment the motif completed.

So a second, separately-parameterised classifier reads the same three memories at the decision step — the event index where \(B \to C\) occurs. For negatives, where no such event exists, the decision step is defined as the last event with \(t \le t_2^{\text{counterfactual}}\), so both classes are evaluated at the same temporal boundary rather than comparing a motif-time snapshot against an arbitrary one. The two are trained jointly:

\[ \mathcal{L} = \mathrm{BCE}\big(\text{logit}_{\text{final}},\, \tilde y\big) \;+\; 0.5 \cdot \mathrm{BCE}\big(\text{logit}_{\text{completion}},\, \tilde y\big), \qquad \tilde y = 0.9y + 0.05 \]
Design decision: label smoothing, for an interpretability-specific reason

The \(\tilde y = 0.9y + 0.05\) is label smoothing, and the usual justifications — calibration, regularisation, reduced overconfidence — are not the reason it is here.

The reason is dynamic range for the instruments. BCEWithLogitsLoss against hard 0/1 targets has no finite minimiser: the gradient keeps pushing \(|{\text{logit}}|\) upward, and a well-fit model ends up at logits of ±15 or beyond, where \(\sigma\) is flat to machine precision. At that point every intervention moves the probability by approximately nothing, causal effects are unmeasurable, and the whole patching apparatus returns zeros that look like findings.

Smoothing to \([0.05, 0.95]\) puts the optimum at a finite logit — \(\sigma^{-1}(0.95) \approx 2.94\) — keeping the model on the responsive part of the curve. This is a case of a training choice made to serve measurement rather than accuracy, and it is worth noticing because it has a cost: the reported accuracies are of a deliberately less confident model than one would ship.

The optimiser is Adam with weight_decay=1e-3 and gradient clipping at norm 1.0. The clipping is not optional here: backpropagation through ~40 sequential GRU steps is exactly the regime where a single bad batch produces a gradient spike that destroys the memory weights, and because the memory is recurrent, one such step corrupts every subsequent forward pass rather than just the current one.

The baseline that could have ended the project

models/flat_gru.py is a deliberate attempt at self-refutation. It is a standard nn.GRU over the flat event sequence with learnable node embeddings and no per-node memory at all. Its docstring states the stakes plainly: if Flat-GRU matches the TGN, then per-node memory is unnecessary and every finding about memory circuits is uninteresting.

The comparison is constructed to be fair rather than favourable. Flat-GRU gets the same time encoding, the same edge features, the same classifier head shape, and also gets the candidate nodes' learned embeddings concatenated at readout — so it is not handicapped on identifying which three nodes matter. It uses pack_padded_sequence so the recurrence genuinely stops at each sequence's real length rather than running over padding. What it lacks is the one thing under test: state indexed by node rather than by position in the stream.

Running the baseline and reporting it is the difference between a study and a demonstration.

05The interpretability toolkit, from first principles

Every method used here comes from the transformer-interpretability literature. Since the project's contribution is porting them, it is worth stating precisely what each one is, what it assumes, and how it fails.

Why correlation is not enough

The oldest interpretability method is the probe: train a small classifier to predict property \(P\) from activation \(a\); if it succeeds, conclude that \(a\) encodes \(P\). The method is cheap and the conclusion is nearly worthless, for a reason that is easy to state and easy to forget.

A probe measures decodability: whether \(P\) is recoverable from \(a\) by some function. It says nothing about whether the model recovers it, or uses it. An activation can carry a feature in a subspace that every downstream weight matrix happens to project away. With enough probe capacity you can decode nearly anything from nearly any wide activation — including properties the model demonstrably does not act on.

This project contains an unusually clean demonstration (§8): 126 of 128 gate dimensions separate motif from non-motif updates almost perfectly, and clamping them moves the output less than a random reshuffle of the same numbers. Perfect decodability, zero causal relevance.

The fix is to intervene rather than observe — to move from \(P(\text{output} \mid a)\) to \(P(\text{output} \mid \mathrm{do}(a := a'))\), in Pearl's notation. Setting an activation and watching what happens downstream is a genuine causal query, because it cuts the activation off from everything that would normally determine it.

Activation patching

The core technique, also called causal tracing or interchange intervention. The recipe:

  1. Run the model on a clean input; cache activations.
  2. Run it on a corrupted input that flips the output; record the damage.
  3. Run the corrupted input again, but overwrite one activation with its clean-run value.
  4. Measure how much of the damage is undone.
\[ \text{recovery} \;=\; \frac{\ell_{\text{patched}} - \ell_{\text{corrupt}}}{\ell_{\text{clean}} - \ell_{\text{corrupt}}} \]

Recovery near 1 means that activation carried essentially all the information the corruption destroyed; near 0 means it carried none. In causal-mediation terms this is an indirect effect: how much of the treatment's influence on the outcome is routed through this mediator.

Three assumptions are doing work, and each is a place the method breaks:

AssumptionHow it failsWhat this project does about it
The patch reaches the computation you aimed atyou patch a value that is recomputed or ignored downstreamexactly the memory_pre vs memory_state defect in §6; now pinned by a regression test

Ablation, and the choice of corruption value

Ablation is patching with a value that is not from another run. What you replace with determines what you have measured:

VariantReplace withInterpretation and hazard
Zero ablation\(\mathbf{0}\)"delete this." Hazard: zero is not a neutral value — it is a specific point that may be far outside the activation's normal range, so the effect size scales with the activation's norm rather than its importance.
Mean ablationpopulation mean from a pilot set"replace with an uninformative value of the right magnitude." Removes the scale confound; the residual hazard is that the mean may itself be an atypical point for a multimodal distribution.
Resample ablationthe value from a random other inputstays on the data manifold; adds variance, and conflates deletion with substitution.
Permutation controlthe same values, dimensions shuffleda matched null: identical magnitude and marginal distribution, destroyed structure. The workhorse control here — and §9 shows it can itself be invalid.

Experiment 1 builds the "circuit fingerprint" — a heatmap of causal importance over every (event step × intervention point) pair — using mean-ablation, and Experiment 6 exists solely to justify that choice. The argument is the scale confound above: zeroing a bounded time encoding (values in \([-1,1]\)) is a small perturbation, while zeroing an unbounded memory vector is a large one, so zero-ablation ranks components by activation norm as much as by function. Exp 6 tests this directly — per-cell Pearson correlation between the two maps, whether zero-ablation disproportionately affects high-scale activations, and the signal-to-noise ratio of each method, defined as the variance of causal effects over their mean square.

The statistics, and why each one is here

Benjamini–Hochberg FDR correction

Testing 128 memory dimensions at \(\alpha = 0.05\) yields ~6.4 false positives by construction. Bonferroni (\(\alpha/m\)) controls the probability of any false positive, which is far too strict when you expect many true effects and are characterising a population of dimensions rather than confirming one hypothesis. BH instead controls the expected proportion of false discoveries: sort the \(p\)-values ascending, find the largest \(k\) with \(p_{(k)} \le \frac{k}{m}\alpha\), reject everything up to it. Much higher power, and the right error rate for "which dimensions differ."

Bootstrap confidence intervals

The recovery ratio is a ratio of two correlated sums, and no closed-form standard error exists for it. The bootstrap resamples samples (not the numerator and denominator independently), recomputes the ratio 10,000 times, and takes the 2.5th and 97.5th percentiles. Resampling samples is what preserves the pairing: each draw keeps a sample's clean, corrupt and patched logits together, so the correlation between them is carried into the interval rather than assumed away.

Paired tests and permutation nulls

Every arm is run on the same samples, so comparisons are paired — a paired \(t\)-test on the per-sample differences removes between-sample variance, which here is much larger than the effect. Where the null is not analytically tractable, the project uses permutation: construct the null by shuffling the labels or the dimensions, and read the \(p\)-value off the resulting distribution. The hazard, which §9 documents, is that a shuffle can be too destructive to serve as a null.

06The intervention API

The nineteen intervention points are not hooks in PyTorch's sense. They are explicit branches in the forward pass, keyed by a tuple and holding a callable:

logits = model(batch, interventions={
    (m2, 'memory_state_src'): lambda x: clean_mem_B.expand_as(x),
    ('readout', 'mem_A'):     lambda x: clean_mem_A.expand_as(x),
})

Keys are either (event_step_index, point_name) for per-event points or (tag, point_name) for readout and classifier points. When interventions=None — the default, and the case during training — every branch is skipped and the overhead is exactly zero.

Design decision: explicit branches over PyTorch hooks

The idiomatic approach is register_forward_hook / register_forward_pre_hook. It was not used, for four reasons.

  1. Granularity. Hooks attach to modules. The quantities of interest — \(z_t\), \(r_t\), \(\tilde h\) — are intermediate tensors inside one module's forward, with no module boundary to attach to. Decomposing the GRU into six submodules purely to create hook points would make the model harder to read than the explicit branches are.
  2. Time indexing. The same module is called ~40 times per forward pass, once per event step. A hook fires on every call and must infer which step it is on from mutable external state. The tuple key (i, 'point_name') makes the step an explicit part of the address.
  3. Composability. Several points are often patched at once (Experiment 2 sets two; the ceiling arm sets three). A dict of callables composes trivially; a set of registered handles requires bookkeeping to attach and — critically — to remove. A leaked handle silently contaminates every later experiment in the same process.
  4. Readability of the computation. With explicit branches, the forward pass documents its own intervention points in source order. With hooks, the places a model can be intervened on are invisible at the point they take effect.

The cost is 19 if statements in the hot loop. Guarded by if interventions and ..., they are a null-check per point per step when inactive.

The distinction that invalidated an earlier result

The first two rows and the memory_state row look like they do the same thing. They do not, and the difference silently produced a wrong answer that survived into a written draft.

Defect: patching the wrong side of the memory

memory_pre_src replaces the memory value passed to the message function. But TGNMemory.update() re-reads the memory bank independently — it does not receive the value the message function saw. So patching memory_pre_src never sets the node's recurrent state. It perturbs the state only second-hand, through the message, attenuated by the update gate.

Experiment 2 originally used memory_pre_src to "restore the clean mem_B at the B→C step." It could not do that. A near-zero recovery was the expected output whether or not routing existed — the experiment had no power to distinguish its hypotheses.

memory_state_src is the point that can: it replaces \(s\) as read from the bank, so it feeds equations (1)–(4) directly and is carried into the write-back by \(s' = (1-z)\odot s + z \odot \tilde h\). Measured on an untrained model, the state patch moves the readout ≈33× more than the message-side patch. tests/test_memory_intervention.py pins the distinction so it cannot regress.

Why this class of bug is dangerous: it does not throw. It produces a plausible number — a small recovery ratio — that reads as a scientific finding ("B's memory carries little") when it is in fact a statement about the instrument ("this probe cannot reach B's memory"). Nothing short of a positive control distinguishes the two, which is the argument for ceiling arms in §9.

The corrected Experiment 2 sets both points, so the counterfactual is complete: "B's memory at this step was the clean one" in every sense.

Observational hooks survive intervention

A subtler piece of hygiene: TGNMemory.update() records each quantity twice — gates / gates_raw, h_tilde / h_tilde_raw, pre_update / state_used. The _raw and pre_update variants capture the values the model itself computed, before any intervention was applied. Without this, an observational analysis run during an intervened forward pass would report back whatever you injected, and the measurement would be circular. On a clean pass the two are identical.

This matters for a specific experiment design: §8's causal arms need to clamp a gate and report what the model's own gate would have been, in the same run. Storing only the post-intervention value would make that impossible without a second forward pass, and a second pass introduces its own divergence under dropout.

Padding is a no-op, and that had already broken two experiments

Every sample is padded to a global maximum event count behind a boolean mask, and writes at padded steps are explicit no-ops (torch.where(mask, memory_new, mem); padded events are routed to a dummy node at index num_nodes). The dummy slot is a neat trick — rather than branching on the mask to skip a write, every write happens and the harmless ones land in a slot nothing reads — but it means the number of steps is not the number of real steps, and two experiments ignored that:

  • Experiment 8 drew its random control step from the padded range, so roughly half of all control interventions did nothing at all. That inflated the control baseline — which is precisely the scientific control for the knockout claim.
  • Experiment 6 swept the padded range and computed pilot means over it. Both importance maps then shared identical zero cells, inflating the correlation between them, and the mean-ablation target was contaminated with dummy-node activations.

tests/test_padding_and_hooks.py pins both, and also pins the hook indexing convention (2*i source, 2*i+1 destination) — an off-by-one there would analyse the wrong node and produce plausible, wrong numbers.

07The central finding: accumulation, not routing

Here is the question the study exists to answer. The model must combine information about \(A\), \(B\) and \(C\). There are two architecturally plausible ways it could do that.

Hypothesis R
Compositional routing
Information about \(A\) is written into \(B\)'s memory at the \(A\to B\) event, carried there, and read out through \(B\). \(B\)'s memory is a relay. This is the "circuit" story, and the analogue of a transformer induction head.
Hypothesis I
Independent accumulation
Each of the three memories evolves on its own, absorbing whatever events touch it. The classifier head does all the combining, at the end, from three separately-grown vectors.

The two hypotheses disagree sharply about source_shuffle. If the chain's origin changes from \(A\) to \(X\), where does the damage live? Under routing, in \(B\)'s memory (the relay now carries the wrong identity). Under accumulation, in \(A\)'s own memory slot (\(A\) was simply never touched by the motif edge). That disagreement is what makes source_shuffle the right diagnostic — and it is worth noting that the other four corruptions are not diagnostic here, because both hypotheses predict the same thing for them.

The measurement

For each positive sample, run a clean pass and a source-shuffled pass; then restore some clean activation into the corrupted run and measure how much of the lost logit comes back:

\[ \text{recovery} \;=\; \frac{\overline{\ell_{\text{patched}}} - \overline{\ell_{\text{corrupt}}}}{\overline{\ell_{\text{clean}}} - \overline{\ell_{\text{corrupt}}}} \]
Design decision: ratio of means, not mean of ratios

The code computes both and reports the ratio of means as primary. The difference is not cosmetic.

The per-sample ratio \(\frac{\ell^{(i)}_{\text{patched}} - \ell^{(i)}_{\text{corrupt}}}{\ell^{(i)}_{\text{clean}} - \ell^{(i)}_{\text{corrupt}}}\) has a denominator that can approach zero for any sample the corruption barely moved. Those samples produce enormous ratios of either sign, and the mean of the ratios is dominated by them — it is a heavy-tailed statistic whose variance may not exist in any useful sense.

The ratio of means weights each sample by how much the corruption actually damaged it, which is the sensible weighting: a sample where the corruption did nothing contributes little information about what the patch restores.

Two further guards back this up. Samples with \(|\ell_{\text{clean}} - \ell_{\text{corrupt}}| < 0.01\) are dropped, and if fewer than 10 usable samples survive the experiment refuses to report at all — returning an explicit insufficient_samples record instead of a number. That branch fires routinely on an undertrained model, where the corruption does not yet damage the prediction and every "result" would be noise dressed as a finding.

Four arms, not one

A bare recovery number means nothing. Experiment 2 runs four conditions per sample:

ArmInterventionRole

mismatchedinject another sample's clean mem_Bthe null — controls for "injecting anything does something"

The mismatched arm uses a derangement — a cyclic shift by a random offset — so no sample can receive its own memory back by accident. A naive random permutation would leave roughly one sample in \(e\) fixed, and each such sample silently converts a null-arm observation into a test-arm observation, biasing the null upward.

Independent accumulation wins. \(B\)'s memory does carry something — 19.8% is not zero, and the interval excludes it decisively — but \(A\)'s own slot carries nearly twice as much. The model is not routing \(A\)'s identity through \(B\); it is growing three memories in parallel and letting the classifier head do the joining.

This is a negative result about circuits, and it is the more interesting outcome. The transformer interpretability canon is built on finding routing circuits — induction heads, indirect-object-identification circuits, name-mover heads — and the implicit expectation is that other architectures have them too. In this one, with this task, at this scale, the mechanism is flatter than that. A plausible reading: the architecture does not need routing here. The classifier sees all three memories simultaneously and has the capacity to combine them, so there is no gradient pressure to build a relay. Routing circuits may be what you get when the architecture forces information through a bottleneck — which is exactly the situation of an autoregressive transformer moving information between token positions.

Experiment 2b: does it hold for all five corruptions?

Experiment 2 answers the question for source_shuffle only. Experiment 2b runs the decomposition for all five, with one design change: every arm injects at the readout rather than at the B→C step. The reason is that "B's memory at the B→C step" is not even well-defined for topology_break or edge_deletion, which replace that edge entirely — \(B\) is not the source at that step and there is nothing to restore. The readout is defined for every corruption and is the site the classifier actually consumes, which makes the arms comparable across strategies.

Two further design notes in that file are worth repeating because they are the kind of detail that decides whether a comparison is valid:

  • Re-sorting. timing_break and temporal_misordering change timestamps, and the model consumes events in sequence order. Both corruptions therefore re-sort the real events afterwards, matching what the generator does. Without this, sequence order and timestamps disagree and the model sees an input off its training distribution — so the measured "damage" would partly be distribution shift rather than the corruption.
  • Replacement-edge sampling. edge_deletion draws its replacement from non-candidate nodes only. The generator draws from all nodes and validates afterwards; drawing outside the candidate set guarantees the same property by construction and avoids a rejection loop whose acceptance rate would vary by sample.

The verdict at the readout is uniform and stark: \(B\)'s memory is not sample-specific for any of the five. The matched-minus-mismatched contrast is \(\le 0.05\) in every case, with every \(p \ge 0.387\). Injecting a clean mem_B does as well as injecting the clean one.

Experiment 2d: where the specificity goes

Those two results are in tension. At the B→C step, \(B\)'s memory is strongly sample-specific (matched beats mismatched by \(+1.17\), \(p < 10^{-4}\)). At the readout, it is not specific at all. Both cannot describe a static quantity — something destroys the specificity in between.

The hypothesis is mechanical: \(B\)'s memory is a fixed-size slot that every subsequent event touching \(B\) rewrites through the GRU. Experiment 2d tests it by stratifying samples on \(q\), the number of times \(B\) is updated after the decision step, and running matched/mismatched patches at both sites. The step-level contrast is the positive control — it should stay large regardless of \(q\), since it is measured before any overwriting can occur.

If readout contrast is large at \(q=0\) and falls as \(q\) grows, overwriting is the mechanism, and the completion-time readout's advantage has the same cause: reading earlier reads a trace that later events have not yet destroyed. This is a concrete, architecture-level limitation of per-node-memory TGNs — a bounded-capacity slot that cannot refuse a write — and it is the kind of finding that only falls out of a causal study.

Note what the GRU's own equations say about this. Writing is \(s' = (1-z)\odot s + z\odot\tilde h\), so old content survives a write by the factor \((1-z)\) per dimension. After \(q\) subsequent writes, a dimension retains roughly \(\prod_{j=1}^{q}(1 - z_j)\) of its original value. For any \(z\) bounded away from zero this decays geometrically in \(q\) — and the gate cannot be zero on average, because a gate that never writes would make the memory useless. The architecture therefore has a built-in forgetting rate it cannot opt out of, and the only free parameter is how fast.

Experiment 2c: is 20% a floor or an estimate?

The report names this as the most serious remaining limitation of Experiment 2, and then goes and bounds it. Replacing all 128 dimensions of mem_B recovers ~20%. But if routing were confined to a handful of coordinates, a whole-vector patch would partly wash it out — a 128-dimensional vector has ample room to carry an identity signature in a small subspace. So 20% is a lower bound, not an estimate, unless you check.

Experiment 2c patches only \(k\) dimensions back to clean, for \(k\) on a geometric sweep from 1 to 128, under two orderings:

  • delta — dimensions ranked by \(|{\text{clean}} - {\text{corrupt}}|\) averaged across samples. If a signature exists anywhere, these are the coordinates carrying it.
  • random — random subspaces of the same size, resampled per sample. The matched null, controlling for the fact that patching any \(k\) dimensions moves the logit somewhat.

The answer: recovery localises to 16 of 128 coordinates, with random subspaces of equal size recovering about 6× less. So the content is concentrated, and the whole-vector number does understate it — but the concentration is in a 12.5% subspace, not a 1% one, and it does not change the ranking against patch_A. The \(k=128\) point is retained as an internal consistency check: it must reproduce Experiment 2's whole-vector number exactly, and it does.

One caveat on the ranking method, stated because it bounds the claim: dimensions are selected by the same corruption whose damage is then measured. That is a mild form of selection on the outcome. The random-subspace control is what makes the comparison interpretable — it is subject to no such selection, so the 6× gap is a real difference in recoverable content — but the absolute 16-dimension figure should be read as "recovery concentrates in roughly this many coordinates," not as the identification of a fixed 16-dimensional feature.

08The gates: discriminable but causally inert

Half the model's parameters are in the GRU. If the model has learned to recognise a motif, a natural place to look is the update gate \(z_t\): does \(B\)'s gate behave differently when the motif edge arrives than when a noise edge does?

Part A — observational

For each positive sample, extract \(z_t\) and \(r_t\) at \(B\)'s motif update versus a randomly-chosen non-motif update of \(B\), and test per-dimension discriminability with paired \(t\)-tests under Benjamini–Hochberg FDR correction.

The gates are, observationally, extremely discriminable: 100 of 128 dimensions for one gate and 126 of 128 for the other separate motif from non-motif updates. That looks like a result.

The experiment's own docstring immediately undercuts it. The control — a randomly sampled non-motif update of \(B\) — may differ from the motif update in elapsed time, incoming message, source identity, event position and surrounding context. The analysis establishes that \(B\)'s gates differ between the motif update and some other update. It does not establish motif-specific specialisation. Naming the confound in the same file that produces the number is good practice and uncommon.

Part B — causal

So clamp the gates. Replace \(z_t\) (or \(r_t\)) with its non-motif mean at the motif step and see what happens to the logit, against a matched permutation control: the same values, randomly reassigned across dimensions. The permutation does the same amount of "something" while destroying the motif-specific pattern, which separates "the intervention perturbed the model" from "the intervention removed the thing we care about."

The result: clamping either gate moves the logit less than its permutation control does. The motif-specific deviation in the gates is causally inert, despite 100/128 and 126/128 dimensions being observationally discriminable.

The general lesson

This is a clean, quantified instance of the central failure mode in interpretability: observational discriminability does not imply causal relevance. A probe can read a feature off an activation with high accuracy while that feature contributes nothing to the computation downstream. Here the gap is as wide as it gets — near-total linear separability, and a causal effect smaller than a random reshuffle of the same numbers.

Experiment 3c — is it the gate, or is it the clamp?

That null is only trustworthy if the clamp was capable of showing an effect. Read equation (4) again:

\[ s' = (1 - z)\odot s + z \odot \tilde h \]

Clamping \(z\) changes how much of the candidate is written, leaving \(\tilde h\) intact. The motif signal still arrives — merely attenuated. A small clamping effect is therefore consistent with two very different worlds: one where the write pathway carries nothing, and one where it carries a great deal but the clamp is too blunt to interrupt it. Experiment 3b cannot separate them, and saying "the gates are causally inert" without separating them overstates what was measured.

Experiment 3c intervenes on \(\tilde h\) directly through the h_candidate_* point, which changes what is written with the gate untouched — the content-side counterpart to gate clamping. Six interventions at the \(A\to B\) step, each paired with its own dimension-permuted control built from the same values. Crucially it adds capacity arms: \(z \to 0\) (suppress the write entirely) and \(z \to 1\) (write the candidate wholesale), which measure how much effect is available through this pathway at all.

This is the resolution, and it is a better answer than either simple one. The gate pathway matters enormously: delete it and three-quarters of predictions flip. But the specific motif-vs-noise deviation in the gate values — the thing Part A found so discriminable — contributes nothing detectable. Both statements are true, and only the severity-matched design lets you say both without contradiction.

A confound caught in the author's own prior analysis

Comparing clamp_z (replace the gate with its noise-condition mean — a mild perturbation) directly against h_zero (delete the candidate outright — a severe one) measures the severity difference, not the pathways. The earlier version of this analysis did exactly that and consequently overstated a pathway asymmetry by a factor of 21×. The same zero-vs-mean confound is documented independently in Experiment 6.

The general form of the error: comparing two interventions of different magnitude and attributing the difference to their targets. It is easy to commit because the two interventions have different natural "neutral" values — the neutral value for a gate is its mean, and for a content vector it is arguably zero — so matched severity has to be constructed deliberately rather than falling out of the design.

09Instrument validity as a first-class result

This is the part of the project that is least like a typical interpretability paper, and most worth copying.

Ceiling arms

Every patching claim carries a ceiling arm: restore all three readout memories, so the classifier sees exactly its clean inputs. Recovery must be 1.0 by construction — anything else means the patching machinery is broken, the hook is firing at the wrong index, or the tensor is being broadcast incorrectly. Measured recovery is 1.0000 on all five corruptions. That number is not a finding about the model; it is a receipt for every other number in the study.

It is worth being precise about what a ceiling arm does and does not certify. It confirms that the intervention mechanism works at the readout — that the dict key is right, the callable fires, the shape broadcasts, and the value reaches the classifier. It does not confirm that a per-event point reaches what you think it reaches, which is why the memory_pre defect required its own targeted test rather than being caught by this arm.

A control that failed its own audit

Permutation controls are the workhorse null here, and the project does not assume they work. Experiment 7 runs a shuffled-label null: repeat the Part A gate analysis with the "motif" and "non-motif" designations randomly swapped. If the Part A finding is real, this should show zero significant dimensions after BH correction.

The deeper check is quantitative. A permutation control is only a valid null if shuffling destroys the structure without destroying the magnitude — if it reaches only a small fraction of what outright deletion achieves. The project measured this for each control:

ControlFraction of deletion effect reachedVerdict
Permutation control A97.8%Rejected — shuffling is nearly as destructive as deleting, so it cannot serve as a null
Permutation control B7.2%Validated — perturbs without destroying

Throwing out one of your own controls on a quantitative diagnostic — rather than using it and hoping — is the single most unusual move in the project. A shuffle that reaches 97.8% of deletion is not a null hypothesis; it is a second treatment arm wearing a disguise, and any comparison against it would have understated every effect in the study.

The mechanism behind an invalid shuffle is worth understanding, because it is predictable in advance. If a vector's components are highly heterogeneous — a few large, most near a common value — then permuting dimensions moves the large components to positions where the downstream weights expect small ones, and the resulting activation is far off-manifold. The shuffle has preserved the multiset of values while destroying their assignment, and when assignment is most of the information, that is deletion by another name. The diagnostic — compare against an actual deletion — is cheap and should be routine.

A sign reversal, documented rather than buried

One analysis produced a correlation of \(+0.648\) at \(p = 0.0008\) with \(n = 12\). Extending the same analysis to \(n = 51\) turned it into \(-0.400\) at \(p = 1.0\). The project reports this as a worked caution about small strata rather than quietly dropping it.

The arithmetic is worth internalising: at \(n=12\), the two-tailed 5% critical value for Pearson's \(r\) is about \(0.576\). A correlation of \(0.648\) clears it — comfortably enough to look like a real effect, and with a \(p\)-value under \(10^{-3}\) that reads as strong evidence. It was noise, and it reversed sign entirely on four times the data. Multiply by the number of strata an interpretability study naturally produces (per-corruption, per-layer, per-dimension, per-checkpoint), and a few such findings are guaranteed.

Cross-seed consistency

Experiment 9 asks whether the circuit fingerprint is a property of the architecture and task, or of one lucky initialisation. It loads Experiment 1's importance maps from multiple seeds, computes pairwise Pearson correlation of the flattened maps, and reports the mean — with correlation above 0.8 as the bar for "stable structure." It also checks whether the same memory dimensions are flagged significant across seeds. It runs automatically from compile_results.py whenever ≥2 seeds exist.

The regression suite

Five test files, 22 assertions, no pytest dependency — plain asserts that run anywhere the project runs. Each pins a defect that was actually found:

The silent statistics bug

The Benjamini–Hochberg implementation had a failure mode that produced a plausible-looking negative result. np.argsort sorts NaN last, so adjusted[sorted_idx[-1]] became NaN; Python's min(nan, x) returns NaN when NaN is the first argument, so the NaN propagated down the entire step-up chain. Every adjusted \(p\)-value became NaN, and rejected = adjusted < alpha was then all-False.

The output: "0 of 128 dimensions significant." Which reads exactly like a real finding.

And it was reachable, not theoretical — scipy.stats.ttest_rel returns NaN whenever the paired differences have zero variance, which is entirely realistic for a saturated sigmoid gate dimension.

Design decision: plain asserts, not pytest

The suite is a set of functions with bare assert statements and a run_all.py driver. The stated reason — "they run anywhere the project runs" — is about dependency surface: the experiments run on Kaggle and Colab sessions where adding a dev dependency is friction, and a test suite that cannot be run is not a test suite.

What is given up is real: no fixtures, no parametrisation, no pytest.approx, no selective runs, and failure output is whatever the assert message says. For 22 assertions over a stable API that is an acceptable trade; at ten times the count it would not be. The important property is preserved either way — each test pins a specific defect with a comment explaining what broke and why it mattered.

Finally, the 22-test suite does one more thing: it verifies bit-identical forward passes across the instrumentation refactor. Adding 19 intervention branches to a forward pass is exactly the kind of change that perturbs numerics without anyone noticing — a reordered operation, a different broadcast, an accumulation in a different dtype. Asserting bit-identity (not approximate equality) means every result from before the refactor remains comparable to every result after it.

10Training dynamics: when the algorithm appears

Checkpoints every 5 epochs turn a static study into a developmental one. Five experiments replay the same probes across training. This is cheap — the checkpoints were being written anyway — and it answers a class of question a final-model analysis cannot: not what the model computes, but in what order it learned to.

ExpQuestionMethod
T1When does the compositional pathway become causally load-bearing?zero-ablate mem_B at the B→C step on fixed positives at every checkpoint; track causal effect, flip rate, accuracy
T2Which corruptions does the model learn to detect first?evaluate a fixed test set at every checkpoint, grouped by corruption type — the model's self-taught curriculum
T3When do \(z_t\) dimensions specialise?per-dimension motif-vs-noise discriminability at each checkpoint
T4Does the time-window boundary sharpen, and when?inject a Δt sweep at the B→C step; track sharpness \(= \ell(4.5) - \ell(5.5)\)
T5Do the learned frequencies know about \(\Delta=5\)?read time_encoder.w from each checkpoint's state dict; flag frequencies with implied period ≈ 5.0

T2 is conceptually the richest: the order in which a model masters the five corruptions is a direct read on which sub-computations are easy and which are hard. edge_deletion (the chain simply does not complete) should be learnable almost immediately; timing_break requires the \(\Delta\) boundary; source_shuffle requires node-identity matching across two events. The ordering of those curves is the model's implicit curriculum, obtained for free from checkpoints that were being saved anyway.

T4's sharpness metric deserves a note on construction. Defining sharpness as \(\ell(4.5) - \ell(5.5)\) — the logit difference across the true boundary — is a deliberately crude two-point estimate of a derivative. The alternative, fitting a sigmoid to the full sweep and reporting its slope parameter, is more precise but introduces a fitting procedure that can itself fail or converge differently across checkpoints, making the trajectory partly an artefact of the fit. A two-point difference has no such failure mode, and for tracking a trend across checkpoints the monotone relationship to true sharpness is all that is required.

Experiment 5 — reading the failure cases

Source-shuffle accuracy sits around 77%, well below the others. Rather than treating that as a number to improve, Experiment 5 treats it as data: partition the source-shuffle negatives into correctly-classified and misclassified, then compare their readout memories (mem_A, mem_B, mem_C) to the positive-sample reference distribution by cosine similarity. What does the model see in the ones it gets wrong?

Cosine similarity is the right metric here rather than Euclidean distance, for a specific reason: memory vectors grow in norm as events accumulate, so a sample with more events touching a node produces a larger vector regardless of content. Euclidean distance would be dominated by that norm difference — effectively measuring event count. Cosine isolates direction, which is the part that plausibly carries content.

This is the right reflex generally. A 77% accuracy on one corruption class, when the others are higher, is a pointer at the mechanism — it says the identity-matching sub-computation is the weak one, which is precisely consistent with the independent-accumulation finding. If the model never routes \(A\)'s identity through \(B\), then detecting that the origin changed is the hardest of the five discriminations, because it depends entirely on \(A\)'s own slot having been left untouched.

11Engineering decisions and the alternatives

Choices that are invisible in the results but determined whether the project was runnable at all.

Batch-vectorised over event index

The forward pass loops over event index, not over samples:

for i in range(max_events):           # ~30–50 iterations
    step_src = src[:, i]              # (B,) — all samples at once
    ...
    self.memory.update(batch_idx, step_src, msg_for_src, ...)

Each sample holds a private memory bank of shape \((B, \text{num\_nodes}+1, d)\), so the per-sample causal ordering is exact while the arithmetic is parallel across the batch. The alternative — looping over samples and processing each one's event stream — is the obvious implementation and is roughly \(B\) times slower, which at batch 32 is the difference between a tractable sweep and an intractable one. The memory cost is the trade: a private bank per sample is \(32 \times 51 \times 128\) floats, which is small, but it is allocated fresh per batch.

Hyperparameter search: Optuna, with alternatives present

tune_hyperparams.py implements three strategies — random, grid, and Bayesian via Optuna — and the Bayesian path is what produced the final configuration (the dropout = 0.108 is the tell). The reasoning follows the standard argument: grid search wastes its budget re-testing unimportant dimensions at every level of the important ones, random search fixes that but has no memory, and Tree-structured Parzen Estimator search models \(p(\text{config} \mid \text{good})\) versus \(p(\text{config}\mid\text{bad})\) and samples where the ratio is favourable. Each trial here is a full training run, so trials are expensive and sample-efficiency is worth the extra machinery.

Keeping all three implemented rather than only the winner is a reasonable call for a research codebase: grid search remains useful for a deliberately exhaustive sweep over two or three parameters when you want the full surface rather than the optimum.

Checkpoint-and-resume as a design constraint

The pipeline is written against a 12-hour Kaggle T4 session with batch_size = 32, and that constraint shapes the architecture of the scripts more than anything else. run_all_seeds.py orchestrates training plus all experiments plus audits across seeds; run_experiments.py selects by name or category; run_exp7_standalone.py exists specifically because the permutation test is expensive enough to need its own session. Experiments are ordered so cheap ones yield results first and expensive ones run last — which means a session that dies at hour 11 still produced something.

This is unglamorous and it is why the project has results. A monolithic script that must run to completion on a session that can be pre-empted produces nothing.

Why PyTorch

Define-by-run is close to a requirement here rather than a preference. The intervention API passes arbitrary Python callables into the forward pass, keyed by runtime values, with control flow that depends on which keys are present. In a define-and-run graph framework that pattern needs the intervention points baked into the graph at trace time, which defeats the purpose. JAX could express it functionally — threading an intervention dict through a scan — but the memory bank is mutable state updated in a loop, which is exactly what functional purity makes awkward. PyTorch Geometric supplies TemporalData and the batching utilities, so the data layer is standard even though the model is hand-rolled.

12Why this matters outside the lab

The deployment context

Temporal graph models are already live in places where their decisions have consequences: payment-fraud detection, money-laundering typology detection, coordinated-inauthentic-behaviour detection on social platforms, lateral-movement detection in network security, recommendation over interaction streams. In several of these, there is a regulatory expectation of explanation — adverse-action notices under US credit law, GDPR Article 22 in the EU, the EU AI Act's requirements for high-risk systems.

"A temporal graph network flagged this account" is not an explanation. The work needed to make it one has to start with knowing what internal mechanism the architecture actually uses, and this project is a first systematic attempt at that for TGNs specifically.

What the finding implies for practitioners

  • Independent accumulation means attribution is simpler than feared — and weaker than hoped. If the three memories evolve independently, then per-node attribution is meaningful: you can ask "what did \(A\)'s slot contribute?" and get an answer. But it also means the model is not building the compositional representation of the chain that an analyst would reach for. It detects chain completion without representing the chain.
  • Overwriting is an architectural ceiling, not a training problem. Experiment 2d's mechanism — later events destroying earlier traces in a fixed-size slot — bounds how far back a TGN can usefully carry a signal, regardless of how long you train. For fraud patterns that develop over weeks with heavy intervening activity, that is the relevant constraint, and no amount of data fixes it. It also motivates the completion-time readout as a design pattern: read at the decision point, not at the end.
  • Gate-level probes will mislead you. 126 of 128 dimensions separating motif from noise, and no causal effect at all, is a warning about the whole family of "probe the activations, find the feature" methods when applied to recurrent gates.

What it demonstrates methodologically

Strip out the TGN specifics and what remains is a reusable protocol for causal claims about neural networks:

  1. Build a task with a known ground-truth rule and minimal-pair counterfactuals.
  2. Adversarially audit the data generator — and assume your audit is incomplete.
  3. Hand-roll the component you want to inspect; fused kernels are opaque by construction.
  4. Pair every structured intervention with a matched control that does the same amount of "something."
  5. Quantitatively validate the control itself against a deletion reference, and discard it if it fails.
  6. Run ceiling arms so the instrument proves itself on every claim.
  7. Match severity before comparing pathways, and add capacity arms to say how much effect was available.
  8. Pin each fixed defect with a regression test; verify bit-identity across instrumentation changes.
  9. Check stability across seeds; report your own reversals.

Steps 5, 7 and 9 are the ones most often skipped, and they are the three that changed conclusions in this project: a rejected control, a 21× overstated asymmetry, and a sign reversal.

13Honest limits

Stated plainly, because a study whose central contribution is instrument validity should be the first to bound itself.

  • One architecture, one task, one scale. 121,546 parameters, a synthetic three-node motif, 50 nodes. "Independent accumulation" is a finding about this model on this task. A larger TGN with multi-hop attention in the embedding module — which this one deliberately replaces with the identity, per §2 — might compose differently, and the attention layer would supply exactly the bottleneck that routing circuits tend to form around.
  • Synthetic data. The anti-shortcut work is extensive, but a hand-built generator can only defend against shortcuts someone thought of. The 78.2% leak is the proof — it existed through several rounds of defence, and a six-baseline audit could not see it. There is no reason to believe it was the last one.
  • The 16-of-128 subspace is a localisation, not an identification. Experiment 2c shows recovery concentrates; it does not say what those 16 coordinates encode, nor whether the same 16 appear across seeds — a question Experiment 9 is positioned to answer but which needs the multi-seed results to be in hand. The dimensions are also selected using the same corruption whose damage is measured.
  • Observational gate discriminability remains confounded. Experiment 3A's control differs from the motif update in elapsed time, message content, source identity and position. The causal null is clean; the observational number should be read as "B's gates differ between these two updates," full stop.
  • Label smoothing makes the model deliberately less confident. It buys measurable dynamic range for the instruments and costs some accuracy. Reported accuracies are therefore not the accuracies this architecture would reach if trained for accuracy alone.
  • The repository ships the experiment code, not its outputs. Methods here have been verified line by line; the reported statistics are the author's and are reproduced as such. Re-running scripts/run_all_seeds.py regenerates them.
