01The question, and why English–Chinese is the hard case

When a language model represents the sentence "the little prince lived on a tiny planet," is it representing English, or is it representing a small boy on a small world? The two are hard to tell apart from inside the model. They come apart cleanly when you ask whether the same representation predicts what a Mandarin speaker's brain does while hearing the same story.

This is Project C4 of the CSAI 2026 Mechanistic Interpretability track, which comprises five parallel projects (C1–C5) on different datasets and language pairs, each delivering the same three standardised artefacts. C4 draws the hardest pairing in the track.

English and Mandarin differ at every level of linguistic structure — writing system (alphabetic vs. logographic), phonology (non-tonal vs. tonal), morphology (inflectional vs. isolating), and syntax. The one thing they share, in this experiment, is semantic content: both groups heard the same story. That makes C4 the strongest available falsification test for the hypothesis that LLM internal features are genuinely semantic rather than language-specific surface regularities.

The logic is a clean dissociation. Train a mapping from model features to brain activity using only English subjects. Apply it, with no retraining, to Chinese subjects. If the prediction holds, the features cannot be encoding English — the Chinese brains were never shown to the model or to the regression. If it collapses, the features were language-shaped all along.

02What fMRI actually measures

Every methodological choice downstream follows from three physical facts about the signal. They are worth stating before any modelling.

The BOLD signal is a proxy, and a slow one

Functional MRI does not measure neural activity. It measures blood-oxygen-level-dependent contrast: haemoglobin is diamagnetic when oxygenated and paramagnetic when not, so the ratio of the two alters the local magnetic susceptibility and hence the MR signal. When a cortical region becomes more active, local blood flow over-compensates for the oxygen consumed, so oxygenation rises.

Three consequences follow, and each one is a line of code later:

  1. It is delayed and smeared. The haemodynamic response function (HRF) rises over roughly 4–6 seconds, peaks, and undershoots before returning to baseline — total duration 20–30 s for an impulse of neural activity. Neural events are therefore convolved with a slow kernel before they are observed at all.
  2. It is sampled coarsely. One volume every TR = 2.0 s here. Speech arrives at 2–4 words per second, so each fMRI sample integrates several words.
  3. It is noisy. Head motion, cardiac and respiratory cycles, scanner drift and thermal noise all enter. The practical consequence is a noise ceiling: the same subject hearing the same passage twice does not correlate perfectly with themselves, and no model can beat that bound.

Parcellation: 200 regions instead of ~200,000 voxels

A whole-brain scan at 2 mm resolution yields on the order of 200,000 voxels. The pipeline reduces this to 200 cortical parcels using the Schaefer 2018 atlas, which averages voxels within functionally-defined regions derived from resting-state connectivity.

Design decision: parcellation, and the alternatives

Why not voxels? Averaging within a parcel raises signal-to-noise roughly as \(\sqrt{n_{\text{voxels}}}\) for independent noise, cuts the number of regressions from 200,000 to 200, and makes results anatomically interpretable rather than a cloud of coordinates. The cost is spatial resolution: if a feature is encoded in a sub-parcel patch, parcel-averaging dilutes it.

Alternatives: a searchlight analysis fits models in small moving spheres, preserving locality at enormous compute cost and with a multiple-comparisons problem across every sphere. Voxel selection — keeping the top-\(k\) most variable voxels — is what the attention-variant family did instead (top-1000 in MNIColin27 space), which is why those numbers are on a different scale and not comparable to these. ICA or PCA on voxels gives data-driven components that are harder to name anatomically.

Schaefer specifically, rather than the older AAL or Desikan–Killiany atlases, because it is derived from function rather than macro-anatomy, and it comes in resolutions from 100 to 1000 parcels so the granularity is a tunable rather than a given. The activation-function family used the 100-parcel version; this work used 200.

Three alignment problems

1. Language and brain run on different clocks

The model produces one hidden state per token. The scanner produces one volume per two seconds. Bridging them requires knowing when each word was spoken, then pooling the tokens that fall in each 2-second bin. The annotation files give word-level onsets; the code propagates each word's onset to all of its subword tokens:

def build_token_onset_map(words, onsets, tokenizer):
    token_onsets = []
    for word, onset in zip(words, onsets):
        subtokens = tokenizer.encode(" " + str(word), add_special_tokens=False)
        token_onsets.extend([onset] * len(subtokens))
    return np.array(token_onsets, dtype=np.float64)

Assigning every subtoken the word's onset is an approximation — subtokens of a multi-syllable word are not simultaneous — but at TR = 2.0 s the error is far below the sampling interval, so it cannot matter. What can matter is a systematic offset, which is the next point.

A one-token bug worth noticing

The leading space in " " + str(word) is not cosmetic. Byte-pair encoders treat "prince" and " prince" as different tokens, because the space is part of the token in GPT-style BPE. Encoding the full text without a leading space while building the onset map with one produces a one-token offset between the two arrays.

Every hidden state would then be attributed to the wrong moment in time — a drift small enough to survive review and large enough to corrupt every alignment score. The code has an explicit comment marking this as the fix.

The same function also handles the mismatch case defensively: if the onset array ends up shorter than the token array it pads with the last known onset; if longer, it truncates. Either way the two arrays end up the same length, and a silent length mismatch cannot propagate into a misaligned regression.

2. Long text does not fit in a context window

Each story section is far longer than the 128-token window used for extraction. The code chunks with max_tokens=128 and stride=64, giving 64 tokens of overlap, and then keeps only the non-overlapping portion of each chunk's output — tracked as own_start in the chunk spec.

The reason to discard the overlap is causal masking. In a decoder-only model, the hidden state at position \(i\) attends only to positions \(\le i\), so the first token of a chunk has no left context and the next few have very little. Their hidden states represent "this word, cold" rather than "this word, in this narrative." Keeping only tokens that had a full 64-token history means measuring the model's contextual representation rather than its cold start.

The trade-off is compute: a stride of 64 with a window of 128 means every token is processed twice. A stride of 128 (no overlap) would halve the cost and reintroduce the cold-start problem at every chunk boundary.

3. Blood is slow — the lag stack

Rather than assume a single canonical HRF delay, the pipeline stacks five lags:

\[ X_t \;=\; \big[\, h_{t-1} \,\|\, h_{t-2} \,\|\, h_{t-3} \,\|\, h_{t-4} \,\|\, h_{t-5} \,\big] \;\in\; \mathbb{R}^{5d} \]

with \(\tau \in \{1,\ldots,5\}\) TRs covering 2–10 seconds, which brackets the HRF peak.

Design decision: lag stacking vs. HRF convolution

The classical approach convolves the stimulus regressor with a canonical double-gamma HRF and fits one coefficient per feature. That assumes the HRF shape, and HRF shape genuinely varies by cortical region, by subject, and with age and vasculature.

Lag stacking makes no such assumption: it hands the regression five time-shifted copies and lets the fitted weights discover the effective impulse response per parcel. A learned non-negative weighting across the five lags is a discretised HRF. Strictly more expressive than any fixed kernel, and it costs a 5× widening of the design matrix — which is affordable only because ridge is doing the regularising.

The alternatives: fit the HRF per voxel (more parameters, harder to estimate from this much data), or use a basis set such as the canonical HRF plus its temporal and dispersion derivatives (three regressors instead of five, a middle ground that assumes a shape family rather than a shape).

The encoding model

For each parcel \(j\), fit ridge regression from stacked model features to that parcel's time series:

\[ \hat\beta_j = \arg\min_{\beta}\; \lVert y_j - X\beta \rVert_2^2 + \alpha \lVert \beta \rVert_2^2 \qquad\Longrightarrow\qquad \hat\beta_j = (X^\top X + \alpha I)^{-1} X^\top y_j \]

with \(\alpha = 100\). The reported metric is Pearson \(R\) between predicted and held-out actual signal, averaged over the 200 parcels and then over subjects.

Why ridge, specifically

This is not a default — it is forced by the shape of the problem, and the alternatives fail for identifiable reasons.

EstimatorWhy not
OLS\(X\) has \(5 \times 7168 = 35{,}840\) columns against a few hundred time points. \(X^\top X\) is singular — the problem is massively underdetermined and has infinitely many zero-error solutions, none of which generalise. The \(\alpha I\) term is what makes the inverse exist at all; the penalty is doing structural work, not just regularisation.
Lasso (L1)Produces sparse \(\beta\) by selecting among correlated predictors essentially arbitrarily. SAE latents are correlated, so lasso would pick one of a correlated group and zero the rest — fine for prediction, destructive for the Feature Atlas, whose whole purpose is a stable per-parcel weight map. It is also far slower: no closed form, and a coordinate-descent path per parcel per subject.
Elastic netMitigates lasso's arbitrary selection but adds a second hyperparameter to tune across 100 configurations × 84 subjects, for no gain on a metric that does not reward sparsity.

RidgeChosen. Closed form (one solve, reusable across parcels), handles \(p \gg n\), shrinks correlated predictors together rather than choosing between them — which is exactly right when groups of latents genuinely share information — and yields dense, comparable weight maps.

A note on \(\alpha = 100\) as a fixed value rather than a tuned one: tuning \(\alpha\) per parcel per subject per configuration would multiply an already large grid by an inner CV loop. Fixing it trades a little per-cell performance for a uniform treatment across all cells — which is the right trade when the object of study is the comparison between configurations, since a tuned \(\alpha\) would let configurations differ in regularisation strength as well as in representation, confounding the thing being measured.

Cross-validation by story section, not by time point

Folds are GroupKFold with story sections as groups. This is the single most important methodological guard in the pipeline.

Consecutive fMRI time points are heavily autocorrelated — the BOLD signal is smooth on the order of seconds, so \(y_t\) and \(y_{t+1}\) are nearly the same measurement. Under a random split, time point \(t\) lands in train and \(t{+}1\) in test, and a model can score well by interpolating between neighbouring training points without having learned anything about language at all. The reported \(R\) would be a measure of signal smoothness.

Grouping by section guarantees held-out data comes from a passage the regression never saw. This is the most common way encoding-model results get inflated, and the pipeline closes it.

One engineering decision worth naming

The ridge solve was moved to a GPU backend (tagged torch_gpu_dual_v1) with a 256-wide target chunk, letting all 200 parcels be solved in one pass. The arithmetic explains why: the grid is 5 SAE variants × 4 layers × 5 adaptation regimes × 84 subjects, and each cell requires a \(35{,}840 \times 35{,}840\) system — or, via the dual form, an \(n \times n\) one where \(n\) is the number of time points.

That dual formulation is the "dual" in the backend's name and it is the key optimisation. By the matrix inversion lemma,

\[ (X^\top X + \alpha I)^{-1}X^\top \;=\; X^\top (XX^\top + \alpha I)^{-1} \]

so when \(n \ll p\) — a few hundred time points against 35,840 features — one solves an \(n\times n\) system instead of a \(p \times p\) one. That is the difference between a \(35{,}840^3\) factorisation and a \(300^3\) one: roughly nine orders of magnitude. Solving all parcels in one chunked call then amortises the single factorisation across all 200 right-hand sides, because \(XX^\top\) does not depend on which parcel is the target.

Results are cached keyed on (activation_source, variant, latent_dim) plus a ridge_backend tag, so a re-run skips any SAE already trained and any alignment already computed under the same backend. Including the backend in the key is a small but correct detail: numerics differ between CPU and GPU solves, so results from different backends should not be silently mixed.

04Sparse autoencoders: the problem they solve

Superposition, and why hidden states are hard to read

The motivating observation: a transformer has far more features it would like to represent than it has dimensions. Qwen-2.5-0.5B carries \(d = 896\) dimensions per layer, and the number of distinguishable concepts in natural language is vastly larger.

The superposition hypothesis says the model resolves this by packing features into nearly-orthogonal directions rather than exactly-orthogonal ones. This works because of a fact from compressed sensing: in \(d\) dimensions you can place exponentially many unit vectors with pairwise cosine similarity below \(\varepsilon\) (the Johnson–Lindenstrauss bound), and if features are sparse — only a few active at a time — the interference between them is rarely large enough to matter.

The consequence for interpretability is polysemanticity: an individual neuron participates in many unrelated features, so reading neuron 412 tells you nothing coherent. The basis the model computes in is not the basis its features live in.

What an SAE does about it

A sparse autoencoder tries to recover the feature basis. Project the hidden state up into a much wider space, force almost all coordinates to zero, and reconstruct:

\[ z = \mathrm{enc}(x) \in \mathbb{R}^{d_{\text{latent}}}, \qquad \hat x = W_{\text{dec}}\, z, \qquad \mathcal{L} = \lVert x - \hat x \rVert_2^2 + \lambda \lVert z \rVert_1 \]

The bet is that in the wider, sparser basis, individual latents become monosemantic — one latent, one concept. Here \(d_{\text{in}} = 896\) and \(d_{\text{latent}} = 7168\), an 8× expansion.

Two parts of that loss deserve unpacking:

  • Why L1 and not L0. The quantity actually wanted is \(\lVert z\rVert_0\), the count of non-zeros. That is non-differentiable and combinatorial. L1 is its tightest convex relaxation, and — this is the useful property — minimising an L1 penalty subject to a reconstruction constraint provably recovers sparse solutions under conditions studied in compressed sensing. L1 is a computational stand-in for the thing you want.
  • Why the decoder has no bias. nn.Linear(d_latent, d_in, bias=False). A decoder bias would let the model reconstruct a constant offset "for free" without spending any latent on it, which both inflates apparent reconstruction quality and means the latents no longer span the represented content.

The five variants, and what each one fixes

All five live in one unified SparseAutoencoder class, differing only in the encoder's non-linearity and in what the decoder does with the result. Each variant exists because the vanilla recipe has a specific known pathology.

VariantEncoderThe pathology it addresses
Vanilla\(z = \mathrm{ReLU}(W_e x + b_e)\)none — this is the monosemanticity baseline everything else is measured against
Gated\(z = \mathbb{1}[W_g x > 0] \odot \mathrm{ReLU}(W_m x + b_m)\)Shrinkage bias. In a vanilla SAE the L1 term penalises every active latent's magnitude, so it does not only deactivate spurious latents — it also systematically under-estimates the magnitude of genuine ones. Separating the which latents fire decision (a gate, which L1 acts on) from the how much decision (a magnitude path, which it does not) lets the penalty enforce sparsity without distorting amplitude.
JumpReLU\(z = z_{\text{pre}} \odot \mathbb{1}[z_{\text{pre}} > \mathrm{softplus}(\theta)]\)Same shrinkage problem, different fix: a learnable per-latent threshold replaces the global penalty. Below threshold, exactly zero; above it, the value passes through unshrunk. The softplus keeps \(\theta\) positive while remaining differentiable — a raw parameter could go negative and make the threshold meaningless.
BatchTopKkeep the top \(k \cdot B\) activations across the whole batchSparsity is a hyperparameter you cannot control. With an L1 penalty, the achieved sparsity depends on \(\lambda\) in a way that must be tuned per layer and per model. A top-\(k\) constraint sets it exactly, by construction. Note the loss has no L1 term at all — sparsity is structural, so penalising magnitude would only reintroduce shrinkage.
Hierarchical
(Matryoshka)		\(z = \mathrm{ReLU}(W_e x + b_e)\), decoded at nested prefix lengthsNo notion of feature importance. A vanilla SAE's latents are unordered. Here, prefixes of sizes \(\{d/8, d/4, d/2, d\}\) each get their own decoder and each must reconstruct \(x\) alone, forcing the first latents to carry the coarsest, most important structure — a learned ordering, analogous to PCA's eigenvalue ordering but in a sparse basis.

The BatchTopK implementation is worth reading for how it achieves a batch-level budget in one topk call over a flattened tensor:

z = F.relu(z_pre)
k = min(self.topk * z.shape[0], z.numel())
flat = z.reshape(-1)
_, flat_idx = torch.topk(flat, k=k)
mask = torch.zeros_like(flat).scatter_(0, flat_idx, 1.0).reshape_as(z)
return z * mask

This is a batch budget, not a per-token one, and the distinction is the point of BatchTopK over plain TopK: a token carrying unusual content can spend more than \(k\) latents if a neighbouring token spends fewer. Per-token TopK forces every token to use exactly \(k\) features, including tokens that need two. The cost is that the sparsity of any individual token now depends on its batch-mates, which makes inference mildly batch-dependent.

And the loss function, which dispatches on variant:

if variant == 'hierarchical':
    total_recon = sum((1.0 / len(x_hat)) * F.mse_loss(xh, x) for xh in x_hat)
    return total_recon + l1_lambda * z.abs().mean()
if variant == 'batchtopk':
    return F.mse_loss(x_hat, x)          # no L1 — sparsity is structural
return F.mse_loss(x_hat, x) + l1_lambda * z.abs().mean()

Training uses AdamW with a cosine LR schedule, gradient clipping at norm 1.0, and checkpoint-on-best-validation-reconstruction. AdamW rather than Adam matters here: the two differ in whether weight decay is coupled to the adaptive learning rate, and for a model whose decoder weights determine the feature directions, decoupled decay gives more predictable shrinkage. The cosine schedule anneals to near zero, which stabilises the final feature directions — a constant LR leaves the latents still drifting at the point you checkpoint them.

05Adaptation: SI, IT, LoRA, QLoRA, DoRA

The grid varies not only the SAE but how the backbone was adapted before hidden states were extracted. These five regimes are a ladder of increasing intervention, and each rung introduces a confound the previous one did not have.

RegimeTrainable paramsWhat it is
SI — straight inference0frozen pretrained weights; the cleanest baseline, since any alignment is attributable to representation quality rather than task adaptation
IT — instruction tunedfullQwen-2.5-0.5B-Instruct, i.e. a different checkpoint rather than a fine-tune performed here

The ordering is deliberate and follows the track specification: straight inference first because it is the cleanest scientific baseline, instruction tuning only when the task format demands it, then LoRA, then QLoRA when memory is the binding constraint, and more elaborate PEFT methods last. Each step adds a confound; taking them in order means you know which one introduced it.

Why parameter-efficient fine-tuning exists

Full fine-tuning updates every weight. For a 0.5B model in fp16 that means 1 GB of weights, 1 GB of gradients, and — because Adam keeps first and second moments per parameter in fp32 — another 4 GB of optimiser state, before activations. Roughly 6–8 GB to train a model whose weights are 1 GB, and the ratio worsens with scale.

It is also wasteful if the hypothesis behind LoRA holds: that the weight update required to adapt a pretrained model to a new task has low intrinsic rank, even though the weights themselves are full-rank.

LoRA, mechanically

Freeze \(W_0 \in \mathbb{R}^{d \times k}\). Learn a low-rank correction:

\[ W = W_0 + \Delta W = W_0 + \frac{\alpha}{r} BA, \qquad B \in \mathbb{R}^{d\times r},\; A \in \mathbb{R}^{r \times k},\; r \ll \min(d,k) \]

Here \(r = 8\) and \(\alpha = 16\), so the scaling factor \(\alpha/r = 2\). Trainable parameters drop from \(dk\) to \(r(d+k)\) — for a \(896\times896\) projection, from 802,816 to 14,336, a 98.2% reduction per matrix.

Two implementation details matter:

  • Initialisation is asymmetric. \(A\) is random (Gaussian or Kaiming), \(B\) is zero. So \(\Delta W = BA = 0\) at step zero and the adapted model is exactly the pretrained model. Training starts from the pretrained function rather than a perturbation of it. Initialising both randomly would inject noise into a model that was already good.
  • The \(\alpha/r\) scaling decouples rank from effective learning rate. Without it, raising \(r\) would increase the magnitude of \(\Delta W\) and implicitly change the step size, so rank could not be swept independently.

At inference, \(BA\) can be folded into \(W_0\), so a merged LoRA model has zero added latency — unlike adapter layers, which insert extra modules into the forward pass and cost latency permanently.

Which modules get adapted, and why that is a scientific choice

PEFT_TARGET_MODULES = ['q_proj', 'k_proj', 'v_proj', 'o_proj']
PEFT_LORA_R = 8 · PEFT_LORA_ALPHA = 16 · PEFT_LORA_DROPOUT = 0.05
PEFT_TRAIN_EPOCHS = 2 · PEFT_LEARNING_RATE = 2e-4

Attention projections only — the MLP blocks are untouched. In the original LoRA paper, adapting attention proved sufficient for most tasks. In this study it is also a confound control: the sibling experiments sweep activation functions (which live in the MLP) and positional encodings. Adapting MLP weights would mean the activation-function comparison was partly a comparison of how well each activation tolerated LoRA. The report states this rationale explicitly, and it is the kind of discipline that distinguishes a controlled sweep from a leaderboard.

The learning rate of \(2\times10^{-4}\) is two orders of magnitude above a typical full fine-tuning rate (\(\sim2\times10^{-5}\)). That is standard for LoRA and follows from the zero-initialised \(B\): the adapter starts with no effect and must move meaningfully within a short budget, and it cannot damage the pretrained weights because those are frozen.

QLoRA and NF4 quantisation

QLoRA keeps LoRA's adapters and additionally quantises the frozen base to 4 bits:

QUANT_CONFIG = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_compute_dtype=torch.float16,
    bnb_4bit_quant_type='nf4',
    bnb_4bit_use_double_quant=True,
)

Three distinct ideas in four lines:

  1. NF4 — NormalFloat4. Ordinary 4-bit quantisation spaces its 16 levels uniformly. But neural network weights are approximately zero-centred Gaussian, so uniform levels waste most of their resolution on tails that are nearly empty. NF4 places its levels at the quantiles of a standard normal, so each level is equally likely to be used — information-theoretically optimal for Gaussian data, and a strictly better use of 16 symbols.
  2. Double quantisation. Quantisation works in blocks, each with its own fp32 scale constant. At one constant per 64 weights, those constants themselves cost \(32/64 = 0.5\) bits per weight — more than 10% of the 4-bit budget. Double quantisation quantises the constants too, recovering roughly 0.37 bits per parameter.
  3. Compute dtype fp16. Weights are stored in 4 bits and dequantised to fp16 for each matmul. Nothing computes in 4-bit arithmetic. The saving is memory, not FLOPs — and the dequantisation kernel is real added work, which is why QLoRA is slower than LoRA despite using less memory.

Gradients still flow through the frozen quantised weights to reach the adapters; the base is never updated, so quantisation error does not compound.

DoRA

Weight-Decomposed Low-Rank Adaptation starts from an observation about what full fine-tuning actually does: decompose any weight matrix into a magnitude and a direction,

\[ W = m \cdot \frac{V}{\lVert V \rVert_c} \]

where \(m\) is a per-column magnitude vector and the fraction is the normalised direction. Empirically, full fine-tuning makes large changes to magnitude with small directional changes; LoRA tends to couple the two. DoRA trains \(m\) directly and applies the LoRA update only to \(V\), decoupling them — hence the ~0.2M extra parameters over LoRA, which are precisely the magnitude vectors.

The reported benefit is better training stability, and this study offers a small independent data point: DoRA is the best regime for the Gated SAE in the stability table, though the margin is inside the noise.

Design decision: why PEFT at all, when the backbone could be frozen

SI — frozen weights — is the cleanest baseline, and arguably the most scientifically interpretable. The adaptation regimes exist to answer a different question: does task adaptation make representations more or less brain-like?

That matters because the two plausible answers are both interesting. Adaptation could sharpen the semantic content (more brain-like), or it could specialise the model toward a task format the brain is not performing (less brain-like). The grid measures which happens, and the answer is not uniform — LoRA wins for three SAE variants on per-subject stability, while the base model wins on the best-configuration Feature Atlas and QLoRA wins the zero-shot transfer benchmark outright.

The alternative design — one regime, chosen by argument — would have produced a cleaner story and a weaker one.

Two things stand out. First, all five variants peak at layer 11 — the middle of a 24-layer model. That is a textbook finding in the brain-encoding literature: early layers carry lexical and surface form, late layers specialise toward next-token prediction, and the middle carries the abstract semantic content that the brain's language network is also computing. The architectural choice shifts the magnitude, never the location.

Layers were selected by fraction of depth — \(\{0.25, 0.5, 0.75, 1.0\}\) of 24 layers, giving 5, 11, 17 and 23 — rather than by absolute index. That is deliberate: fractional selection makes the sweep comparable across models of different depths, which matters for a track whose sibling projects use backbones of 2, 3 and 12 layers.

Second, the two variants that win are the two simplest. Vanilla and Gated beat JumpReLU and BatchTopK by roughly 40%. The variants engineered for better reconstruction fidelity are not the variants that best predict brains — a direct instance of a tension running through the SAE literature. One plausible mechanism: a hard sparsity constraint (BatchTopK) or an aggressive threshold (JumpReLU) discards low-magnitude latents, and in a distributed semantic code the many small contributions may be exactly what the ridge regression needs. Optimising for reconstruction of the dominant directions is not the same as preserving the information a downstream linear readout can use.

Reading the R values honestly

\(R \approx 0.08\) sounds low if you are used to machine-learning benchmarks. It is not, in this setting. fMRI has a low noise ceiling: the same subject listening to the same passage twice correlates with itself only modestly, and that self-correlation upper-bounds what any model can achieve. These values are in the normal published range for single-subject parcel-level encoding models and are consistent across 84 subjects and 4 layers.

Note also that the report quotes two different aggregations and they should not be confused: best-configuration R (0.079, the peak cell in the grid) and per-subject mean R (≈0.063, averaged over 336 subject × layer observations). Both appear in the tables here; the headline "0.079" is the former.

The language gap

English subjects score 0.002–0.010 higher than Chinese subjects across all configurations, with the largest advantage for Vanilla SAE (\(\Delta R \approx 0.010\)). 95% confidence intervals cross zero for every variant, so the difference is not statistically significant. Reporting a consistent-direction, non-significant effect as non-significant — rather than as a "trend" — is the correct call.

The resolution

Why both results are true

The SAE cannot reconstruct cross-language activation vectors (MSE 50–200× worse), yet its features predict cross-language brain activity (R retains ~81%).

These are only contradictory if you assume brain alignment requires faithful reconstruction. It does not. Reconstruction demands getting the full 896-dimensional geometry right, including everything language-specific — token statistics, morphological structure, script-level regularities, positional habits. Brain prediction only demands getting right the subspace the brain also tracks, which is the semantic one.

So the dissociation is informative rather than puzzling. The SAE's latent basis contains two kinds of structure: a large, language-specific component that dominates squared reconstruction error, and a smaller, language-invariant semantic component that survives transfer. The ridge regression, free to weight latents however it likes, selects the second and ignores the first.

The deeper point is about what a loss function measures versus what you care about. MSE is a sum over all 896 dimensions, so it is dominated by whichever components have the largest variance — and those are the language-specific ones. A metric that weights all directions equally will always be dominated by the directions that vary most, which need not be the directions that matter.

The QLoRA result is a second, smaller surprise. QLoRA — LoRA over a 4-bit quantised backbone — achieves the highest cross-language symmetry, beating full-precision LoRA and the frozen base. The plausible mechanism is that NF4 quantisation noise acts as a regulariser: a weight perturbation of bounded magnitude at every layer discourages the backbone from fitting fine-grained, language-specific detail, nudging representations toward coarser structure that transfers. Memory-saving as accidental regularisation is a recurring pattern, and this is a clean instance — though with \(n=5\) subjects it is a strong hint rather than a settled result.

Two findings

SAE features beat every normalization baseline by ~75%. Best SAE \(R = 0.079\) against best norm \(R = 0.045\). Sparse decomposition is not cosmetic — it extracts something from the hidden state that a rescaling of that same state does not expose. Since both operate on identical inputs through an identical pipeline, the gap is attributable to the decomposition itself.

RMSNorm ≈ ScaleNorm ≈ LayerNorm to within \(\Delta R < 0.0001\). Three genuinely different operations produce indistinguishable alignment, and the explanation is exact rather than hand-waved.

Each of the three applies an affine map: subtract something, divide by something, optionally scale and shift. Ridge regression fits \(\hat y = X\beta\). If \(X' = (X - \mathbf{1}c^\top)D\) for a constant vector \(c\) and diagonal \(D\), then any prediction achievable from \(X'\) is achievable from \(X\) by setting \(\beta = D\beta'\) and absorbing the shift into the intercept. The transformation is invertible and linear, so it cannot change the span of the regression's reachable functions — it changes only the parameterisation, and therefore only how the \(\alpha\lVert\beta\rVert^2\) penalty distributes across coordinates. That residual effect is what produces a \(\Delta R\) of order \(10^{-5}\) rather than exactly zero.

Why a null result is worth the compute

Running 100 configurations to discover that three of them are identical looks wasteful until you consider the alternative: publishing an SAE number with nothing to compare it against.

The norm family does three jobs at once. It establishes the floor (0.045) that makes 0.079 interpretable. It confirms the pipeline responds to real representational differences rather than to any perturbation whatsoever — SAEs move the number, rescalings do not. And the RMSNorm/ScaleNorm/LayerNorm equivalence is a positive control on the metric itself: those three should be equivalent under ridge, and if they had differed, something would have been wrong with the measurement rather than interesting about the models.

That last use is the most valuable and the least common. A result you can predict analytically, measured empirically, is a test of your instrument.

Activation functions and positional encodings

Both use a purpose-built TinyCausalTransformer at two scales (tiny: \(d{=}64\), 2L, ~376K params; small: \(d{=}96\), 3L, ~750K), with intfloat/multilingual-e5-small (117.65M params) as a frozen pretrained upper-bound reference. Five activations (ReLU, GELU, GEGLU, SwiGLU, SoLU) and five positional encodings (Sinusoidal, Learned, RoPE, ALiBi, XPOS), swept across poolings, context windows (8/20/45/90 s) and HRF lags (4/6/8/10 s) — 960 and 1440 controlled rows respectively.

Three design choices in that sweep are worth noting. LoRA adapters are restricted to attn.qkv and attn.out only, never the MLP — because adapting MLP weights would confound the activation comparison, and adapting positional embeddings would defeat the PE study. Features are PCA-reduced to 96 components before ridge, both as regularisation and to equalise dimensionality across model scales, so a larger model does not win merely by having wider features. And every condition is paired with a shuffled-label ridge baseline confirming positive \(R\) exceeds chance.

Headline findings: SoLU (\(x \cdot \mathrm{softmax}(x)\), the interpretability-motivated activation designed to encourage monosemantic neurons by suppressing all but the largest activations) is the only activation with positive cross-language transfer, at +0.0056 — a suggestive result given that SoLU and SAEs are two attacks on the same superposition problem. And across all positional encodings the pretrained backbone dominates: capacity and pretraining matter far more than the choice of positional scheme, with sinusoidal best among the controlled variants.

10Why this matters

For interpretability

The field's standing problem is validation. An SAE latent that appears to fire on "references to royalty" might be a real feature or might be a convenient post-hoc story about a direction in activation space. The usual checks are internal — reconstruction loss, sparsity, whether a human finds the top activations coherent — and they are all vulnerable to the same circularity: the model and the explanation come from the same place.

Brain data is an external criterion. A biological system that was never trained on next-token prediction, never saw these activations, and implements language in an entirely different substrate nonetheless shows measurable correspondence with a specific subspace of the model's representations. That correspondence cannot be an artefact of the interpretability method, because the brain is not downstream of it.

The zero-shot cross-language result tightens this further. It is not enough that English features predict English brains; that could reflect shared surface statistics of the English stimulus. English features predicting Mandarin brains, with no refitting, isolates the semantic component — there is no shared surface form left to explain it.

For neuroscience

A longstanding question is whether the brain's language network computes a language-independent semantic representation or runs language-specific machinery end to end. Evidence usually comes from bilingual subjects, who are confounded by proficiency, age of acquisition and switching cost. Here the subjects are monolingual-in-task and the invariance is carried by the model, which provides a shared coordinate system between two groups that share no linguistic surface form at all. The result supports a language-invariant semantic layer, consistent with but methodologically independent of the bilingual literature.

For practice

  • Middle layers, consistently. All five SAE variants peak at layer 11 of 24. If you are extracting features for any semantic downstream task, the middle of the stack is where to look, and the architectural choice does not move that.
  • Simple SAEs won. Vanilla and Gated beat JumpReLU and BatchTopK by ~40% on brain alignment despite the latter being designed for better reconstruction. Optimising an SAE for reconstruction fidelity does not optimise it for representational usefulness — if you care about the second, measure the second.
  • Quantisation may help generalisation. QLoRA's top cross-language symmetry suggests 4-bit noise functions as a regulariser. Worth testing deliberately rather than treating quantisation as a pure cost.
  • Measure your baseline floor. The normalization family exists only to answer "compared to what," and it is what converts 0.079 from a number into a result.
  • Group your CV folds by the right unit. Story section here; subject, site or session elsewhere. Random splits over autocorrelated data inflate scores silently and are the single most common error in this literature.

11Limits worth stating

  • The zero-shot benchmark uses 5 subjects. The headline \(R = 0.064\) is the most important number in the project and rests on the smallest sample in it. The full-grid results use all 84; the transfer result does not, and should be read as a strong indication rather than a settled estimate.
  • Effect sizes sit inside inter-subject variance. Std ≈ mean throughout. The Q4-vs-Q1 subject spread (>0.075 vs <0.035) exceeds the entire best-to-worst variant gap. Architecture rankings are stable in direction but should not be over-read in magnitude.
  • Three metrics are in play and are not interchangeable. SAE/normalization use parcel-wise time-series \(R\) over 200 Schaefer parcels; attention uses LOO pattern \(R\) over top-1000 voxels; activation/PE use PCA-reduced ridge with sliding context windows. The 0.71 attention figure and the 0.079 SAE figure are different quantities. The report's per-family framing is correct; any cross-family comparison of raw numbers is not.
  • One backbone for the SAE work. Everything in §4–§8 rests on Qwen-2.5-0.5B. Layer-11 peaking is well replicated generally, but these specific magnitudes are one-model results, and a 0.5B model is small enough that its middle layers may not be doing what a 70B model's middle layers do.
  • \(\alpha=100\) is fixed, not tuned. Uniform across all cells, which is the right choice for comparing configurations but leaves per-cell performance on the table.
  • No noise ceiling is estimated. Without a repeat-presentation estimate of each subject's self-correlation, \(R = 0.079\) cannot be converted into "x% of the explainable variance." It is an absolute number whose headroom is unknown.
  • Controlled backbones are tiny. The TinyCausalTransformer at 376K–750K parameters, trained on one short novel, is near the floor of what can learn anything. The activation and PE findings are about what survives at that scale — informative because it isolates the component, but not a claim about production-scale models.

Notes on running it in practice

The notebooks are written for Kaggle and the environment handling is more defensive than typical notebook code, for reasons that are worth knowing if you adapt them:

  • They search /kaggle/input recursively for the preprocessed and annotation folders rather than hard-coding a path, because Kaggle dataset mounts nest differently depending on how the dataset was uploaded.
  • When the source root is a read-only /kaggle/input mount, output is redirected to /kaggle/working. Writing to the input mount fails, and the failure appears late.
  • Cached feature paths are rewritten on load — str(p).replace('\\', '/').split('/')[-1] — because the index CSV was generated on Windows and carries backslash paths that break on Linux.
  • There is a monkey-patch disabling a Hugging Face @strict dataclass validator that broke PEFT imports at the version pinned here. It is ugly, it is documented in the cell, and it is the pragmatic answer to a transitive dependency conflict in a hosted environment where you cannot freely downgrade.

None of this is elegant. All of it is the difference between a pipeline that runs on the machine it has and one that only runs on the machine it was written on.
